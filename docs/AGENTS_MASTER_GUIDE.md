# Генеральная инструкция для агентов (Master Operating Guide)

Данный документ является высшим нормативным регламентом для всех агентов, работающих над кодовой базой **PhotoCraft Plugins & Companion**.

---

## 1. Архитектура и зоны ответственности

Проект организован как модульный Cargo Workspace монорепозиторий:

* `crates/core_contracts/` — **Общий слой абстракций**. Трейты, протоколы, структуры данных DTO, типы ошибок (`Result<T, CompanionError>`), модели команд и контракты плагинов.
* `crates/photocraft_bridge/` — **Зона Агента 1 (Мост)**. Асинхронный клиент на `tokio` к сокету PhotoCraft (порт 18492), выполнение JSON-RPC методов (`engine.execute`, `doc.inspect`, буфер обмена).
* `crates/ai_engine/` — **Зона Агента 2 (ИИ-движок)**. Крейт `ort` (ONNX Runtime bindings) для запуска RMBG-1.4 с DirectML (Windows), CoreML (macOS) и CUDA/CPU (Linux/BSD).
* `crates/overlay_ui/` — **Зона Агента 3 (Интерфейс)**. Кроссплатформенная панель на `egui`/`eframe`, оформленная в едином стиле с PhotoCraft.
* `crates/hotkey_service/` — **Служба горячих клавиш**. Кроссплатформенный перехват хоткеев на `global-hotkey` (Windows, macOS, Linux X11/Wayland).
* `crates/companion_app/` — **Главное приложение**. Сборка dependency injection, системный трей (`tray-icon`), точка входа.
* `plugins/` — **Каталог действий**. Конфигурационные манифесты действий (например, `remove_bg`).
* `chronicle_writer` — **Агент-Летописец**. Ведение двуязычной летописи разработки в `docs/CHRONICLE.md` и `CHRONICLE.en.md`.

---

## 2. Железные правила разработки

1. **Изоляция пакетов:**
   * Никаких прямых перекрёстных зависимостей между `photocraft_bridge`, `ai_engine` и `overlay_ui`. Связь только через интерфейсы `core_contracts`.
2. **Бесшовность (In-Place Updates):**
   * Результат работы плагина должен применяться к холсту автоматически.
3. **Регистрация дефектов (`docs/BUGS_AND_ISSUES.md`):**
   * Каждый баг регистрируется с префиксом `BUG-XXX` и статусом `NEW` / `IN_PROGRESS` / `RESOLVED`.
4. **Синхронизация летописи:**
   * Каждая запись ведётся синхронно на русском (`CHRONICLE.md`) и английском (`CHRONICLE.en.md`) с указанием времени: `*Время: ДД месяца ГГГГ, ЧЧ:ММ (~ХХ минут)*`.
5. **Абсолютный запрет завершения без тестов и документации (Definition of Done):**
   * **СТРОГО ЗАПРЕЩЕНО** считать любой этап, задачу, спринт или исправление дефекта завершенным без выполнения двух незыблемых условий:
     * **1. Полное прохождение тестов:** Команда `cargo test --workspace` обязана завершаться с кодом 0 и нулевым количеством упавших тестов. Все новые фичи должны сопровождаться модульными/интеграционными тестами, а интерфейс — проверяться линтером локализации на отсутствие захардкоженных строк.
     * **2. Актуализация всей документации:** Все файлы документации проекта (`docs/CHECKLIST.md`, `docs/BUGS_AND_ISSUES.md`, `docs/CHRONICLE.md`, `docs/CHRONICLE.en.md`) должны быть обновлены в той же итерации, отражая точный реальный статус системы.
6. **ЖЕЛЕЗНОЕ ОГРАНИЧЕНИЕ РЕСУРСОВ ПК ПРИ КОМПИЛЯЦИИ (Resource Guard):**
   * **СТРОГО ЗАПРЕЩЕНО** запускать `cargo build`, `cargo check`, `cargo test` или `cargo clippy` без явного жесткого ограничения нагрузки на CPU и RAM.
   * Обязательно использовать флаг потоков `-j 1` (или максимум `-j 2`) и следить за `codegen-units=1` во избежание зависания системы пользователя и исчерпания памяти.
   * Любые сборки и проверки должны быть максимально щадящими к процессору и оперативной памяти рабочей станции.
