# PhotoCraft Plugins & Companion — Project Context & Operating Guide for Gemini / Antigravity

Добро пожаловать в **PhotoCraft Plugins & Companion** — расширяемую систему плагинов, ИИ-инструментов и интерактивных оверлей-панелей для графического редактора **PhotoCraft** (Rust-based open-source reimplementation of Photoshop).

Проект решает ключевую задачу: **бесшовное расширение функционала PhotoCraft внешними инструментами (нейросети, кастомные хоткеи, плавающие панели кнопок)** без модификации исходного кода самого графического редактора и в обход ограничений изолированной Wasm-песочницы.

---

## 1. Архитектура проекта (Модульный монорепозиторий)

Проект организован по принципу независимых пакетов с чётким разделением ответственности:

photocraft-plugins/

├── README.md                       # Описание проекта и инструкции по сборке

├── docs/                           # Координационный центр разработки (по стандартам Shellit)
│   ├── AGENTS_MASTER_GUIDE.md      # Генеральный регламент работы всех агентов

## 2. Ключевые принципы разработки

1. **Бесшовность для пользователя (In-Place Execution):**
   * Все операции должны происходить прямо в активном документе PhotoCraft без необходимости вручную сохранять или переоткрывать файлы через проводник.
2. **Contract-First & Пакетная изоляция:**
   * Реализации в `photocraft_bridge`, `ai_engine`, `overlay_ui` зависят только от чистых интерфейсов в `core_contracts/`.
3. **Безопасность и портативность:**
   * Все модели и конфигурации по умолчанию хранятся локально в портативной папке (`PhotoCraftData/models/` или директории проекта). Никаких неконтролируемых утечек данных в облако.
4. **Правило Context7:**
   * Использовать только актуальную документацию библиотек и API (`onnxruntime`, Win32 API, PhotoCraft Control Protocol).
5. **Протокол дефектов и летописи (Shellit Standard):**
   * Любые баги не замалчиваются, а фиксируются в `docs/BUGS_AND_ISSUES.md`.
   * Задачи отмечаются в `docs/CHECKLIST.md`.
   * Прогресс фиксируется синхронно на двух языках в `docs/CHRONICLE.md` и `docs/CHRONICLE.en.md` с точными таймштампами.
6. **Критерий завершения этапа (Definition of Done — Форматирование, Тесты и Документация):**
   * **СТРОГО ЗАПРЕЩЕНО** считать любой этап, задачу или исправление дефекта завершенным без:
     1. **Чистоты форматирования кода (`cargo fmt --all -- --check`)** — нулевой допуск к расхождениям стиля;
     2. **100% успешного прохождения всех тестов во всем воркспейсе (`cargo test --workspace -j 1`)**, включая модульные, интеграционные тесты, линтер архитектурной чистоты ядра (`architecture_integrity_test`), линтер регламентов разработки (`dev_regulations_lint_test`), линтер локализации (`i18n_lint_test`) и векторного интерфейса (`vector_first_lint_test`);
     3. **Валидации каталога плагинов** (`cargo run --package plugin_validator -j 1 -- --validate plugins`);
     4. **Приведения в актуальное состояние всей документации проекта**: синхронная отметка чек-листа в `docs/CHECKLIST.md`, регистрация/закрытие дефектов в `docs/BUGS_AND_ISSUES.md` и авторская запись прогресса на двух языках в `docs/CHRONICLE.md` и `docs/CHRONICLE.en.md`.
7. **Железное ограничение потребления ресурсов ПК при компиляции (Resource Guard):**
   * **СТРОГО ЗАПРЕЩЕНО** запускать компиляцию, сборку или тесты на машине пользователя без жесткого ограничения ресурсов.
   * Обязательно использовать `cargo ... -j 1` (максимум `-j 2`) и следить за `codegen-units=1`, не допуская загрузки всех ядер процессора и выедания всей оперативной памяти.
8. **ЖЕЛЕЗНЫЙ ЗАПРЕТ ХАРДКОДА И KEYWORD-SNIFFING (Strict Zero-Core Hardcoding Prohibition):**
   * **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** модифицировать исходный код программы (`companion_app`, `ai_engine`, `photocraft_bridge`) под логику конкретных плагинов:
     - Заниматься keyword-sniffing имен файлов или плагинов через `.contains("depth")`, `.contains("normal")`, `.contains("birefnet")`, `.starts_with()`, `.ends_with()`;
     - Хардкодить имена файлов моделей (`.onnx`, `.bin`, `.safetensors`) в кодовой базе ядра;
     - Подделывать манифесты (`required: false` для моделей `NativeAi`) ради обхода тестов без весов;
     - Писать специальные `match`/`if` под ID плагинов или вшивать специфичные шаги внутрь Rust-кода.
   * **ЦЕЛЬ ПРОЕКТА:** Любой пользователь или сторонний автор должен иметь возможность создать папку в `plugins/`, положить туда `.onnx` и манифест `plugin.json` (или установить `.pcpl`) — и плагин **ОБЯЗАН ЗАРАБОТАТЬ СРАЗУ И ПОЛНОЦЕННО БЕЗ ИЗМЕНЕНИЯ ИСХОДНОГО КОДА ПРОГРАММЫ И БЕЗ ЕЁ ПЕРЕСБОРКИ**.
   * Вся логика рабочего процесса плагина задается **ИСКЛЮЧИТЕЛЬНО ДЕКЛАРАТИВНО В MANIFEST `plugin.json`**:
     - выбор источника входных данных (`input`: `active_layer`, `selection`, `full_canvas`);
     - универсальная задача инференса (`ai`: `segmentation_mask`, `super_resolution`, `inpainting` и т.д.);
     - явный контракт ролей моделей (`models`: `[{ "role": "depth_estimation", ... }]`);
     - цепочка команд до и после ИИ-инференса (`commands` / `post_commands`: например, `["image.revealAll", "layer.mergeDown"]`);
     - режим наложения результата (`output`: `in_place`, `new_layer`, `mask`).
   * Ядро компаньона — это исключительно нейтральный рантайм-интерпретатор манифестов. Любая подгонка кода ядра под плагины вместо реализации декларативного контракта строго запрещена.
9. **ШЛЮЗ ГЛАВНОГО АГЕНТА (Zero-Blind Trust Gateway):**
   * Главный агент **не имеет права принимать отчёт от субагента без личной проверки `git diff`** на предмет костылей, keyword-sniffing и хардкода.
   * Главный агент **не имеет права объявлять пользователю готовность**, пока результат не проверен на реальных граничных условиях (а не на синтетическом квадратике 16x16).
